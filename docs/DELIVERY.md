# 交付说明

## 做了什么

**转发器（`app/`）**

- `relay.py`：单个上联组播套接字收包，按**源 IP** 查当前订阅表，把同一份
  payload 发到订阅该源的每个教室组播端口。订阅表是不可变快照，换订时原子替换，
  数据面不加锁。附带自激回环抑制（教室组与上联组/端口重合时按 payload 短期去重）。
- `table.py`：每个版本最多两个源、端口范围校验、不可变快照。
- `migrations.py`：准备 → 切换前复核 → 统一切换 → 收窄 的状态机；准备失败保持
  旧表并尝试恢复旧源放行；收窄失败按新表继续转发、报告上联**实际**放行范围、
  关闭换订门禁，`retry-narrow` 成功后才放行新换订。
- `uplink.py`：每次改表后都回读模拟器实际过滤；回执丢失时按实际过滤判断，
  回执成功但实际不符时判失败，不把 ACK 当唯一依据。
- `main.py`：Swagger 控制面（`/migrations`、`/migrations/{id}`、
  `/migrations/{id}/retry-narrow`、`/state`、`/stats`、`/demo/*`）。

**模拟器（`simulator/`）**

- 从 `127.0.0.11/12/13` 向同一组播组持续发包；过滤可为整组或最多两个精确源；
  `refuse_changes`（拒绝改表）、`drop_receipts`（先改后断连丢回执），并支持
  `*_only_sources` 只命中准备或只命中收窄。

**编排与演示**

- `docker-compose.yml` / `Dockerfile`：uplink、relay、classroom 观察器。
- `scripts/classroom_watcher.py`：打印每个教室端口当前收到的源。
- `scripts/demo_switch.py`：一条命令跑完换订、准备失败、收窄失败+暂停+重试、
  丢回执五段演示。
- `README.md`：设计、API、配置、限制。

## 测出什么

- 单元/集成：`python3 -m pytest -q` → **33 passed**（约 30 秒），覆盖每版 ≤2 源、
  按源分发、回环抑制、成功/准备失败/收窄失败/重试/丢回执。
- 真实 UDP 端到端（独立进程 + 真实套接字）：
  - 教室端口只收到所订阅源的包；切换时旧源持续到新源在线上出现，
    观测到的重叠窗口约 0.5 秒一个采样周期内，没有断流。
  - 丢回执两次后换订仍 `completed`，步骤记录 `ack=lost, verified_by_actual=true`。
  - 只用「回执丢失 + 实际未变」的模拟，换订判 `prepare_failed`，旧表不变。
  - 旧表 {11,12} → 新表 {13}：准备阶段整组放行，收窄后模拟器实际只剩 `13`，
    观察器显示三个教室端口都从 11/12 切到 13。
  - 收窄被拒绝：新表已生效、教室仍收新源、`gate.blocked=true`，新换订返回
    `blocked`；重试后 `completed` 且门禁恢复。
- 现场演示脚本输出：正常换订、准备失败（旧表不变）、收窄失败+暂停+重试成功、
  丢回执仍成功，均符合预期。

## 没完成 / 已知限制

- 订阅表只在进程内存，重启回到 `RELAY_INITIAL_TABLE`；多副本不同步，
  换订门禁只在单实例内生效。
- 真实上联若没有可回读的过滤接口，只能信 ACK；丢回执会被判失败
  （模拟器提供了回读接口，所以演示里能按实际状态判断）。
- Compose 用 `network_mode: host` + Linux 回环别名，macOS/Windows 不能直接演示。
- 自激回环抑制只在教室组/端口与上联重合时启用，按 payload 去重，不是通用去重。
- 未做鉴权、限流、持久化；`demo/*` 接口只适合本地演示。
- 本环境没有 Docker，Compose 只做了 YAML 结构校验；实际容器启动未验证。
